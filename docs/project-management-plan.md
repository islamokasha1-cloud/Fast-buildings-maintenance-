# مستند تصوّر — نظام إدارة المشاريع (الإنشاء والترميم)

> **اقرأني أولاً.** ده مستند **تصوّر للمراجعة والنقاش قبل كتابة أي كود**. الهدف نتفق على
> الشكل والحقول والمنطق على الورق، وبعدين ننفّذ صح من أول مرة. كل رقم أو مسمّى هنا
> **مبدئي وقابل للتعديل** — علّق عليه وعدّله زي ما تحب.
>
> **الحالة:** مسودّة أولى للنقاش — لم يُكتب أي كود بعد.
> **الفرع:** `claude/bali-project-management-system-126929`

## ١) الفكرة في سطرين

نحوّل «المشروع» من مجرّد **اسم/وسم** بنعلّق عليه طلبات الشراء والبلاغات، إلى **بطاقة مشروع
حقيقية** فيها موازنة وتكلفة فعلية وإيراد وربحية — مربوطة **أوتوماتيك بنظام المشتريات الحالي**.

السؤال اللي المفروض النظام يجاوبه في شاشة واحدة:
> «المشروع ده بيكسّب ولا بيخسّر؟ صرفت كام من المخطط؟ فاضل كام؟ والعميل دفع كام؟»

---

## ٢) المبادئ الحاكمة (مهمة)

1. **نبني فوق الموجود، مش من الصفر.** «المشروع» موجود أصلاً (`meta/projects`)، وكل طلب شراء
   مربوط بمشروع (`projectId`/`projectName`)، والمشتريات **بتحسب المصروف الفعلي لكل مشروع
   بالفعل** من الطلبات المغلقة (`poActualCost` + `poIsClosed`). إحنا بنضيف طبقة فوق، مش بنعيد.
2. **مصدر واحد للحقيقة.** المصروف الفعلي بييجي **حصرياً** من دوال المشتريات المركزية الموجودة
   (`poIsClosed`, `poActualCost`, `_poPaidSoFar`)، فلا يوجد رقمان متناقضان بين المشتريات
   وإدارة المشاريع. أي حساب جديد يمرّ على نفس الدوال.
3. **بنود موازنة هجينة.** بنود عامة ثابتة (عمود فقري للتقارير والربط) + تفاصيل مقايسة لكل
   مشروع تحتها (تفصيل ومرونة). (تفصيل في §٦).
4. **لا انحدار.** المشاريع الحالية (الأمانة `hail` وغيرها) تفضل تشتغل زي ما هي؛ الحقول
   الجديدة كلها **اختيارية** — مشروع بلا موازنة يظهر عادي بموازنة = صفر.
5. **التدرّج.** ٣ مراحل، كل مرحلة تشتغل لوحدها وتدّي قيمة، والبناء تراكمي.

## ٣) نموذج البيانات (مبدئي)

### ٣-١) بطاقة المشروع

نوسّع كائن المشروع في `meta/projects` (الموجود حالياً `{id, name, desc, icon}`) بحقول
اختيارية، والتفاصيل الكبيرة في مستند مستقل لكل مشروع لتفادي تضخّم مستند القائمة:

```
meta/projects  →  projects: [{
  id, name, desc, icon,            // الموجود حالياً — بدون تغيير
  client,                          // اسم العميل
  type,                            // "construction" | "renovation"
  location,                        // الموقع (بالي / العنوان)
  managerUid,                      // مدير المشروع المسؤول
  status,                          // "planning" | "active" | "on_hold" | "closed"
  startDate, endDate,              // تواريخ مخطّطة (نصّية YYYY-MM-DD، نمرّ على _parseLocalDate)
  contractValue,                   // قيمة العقد الإجمالية (الإيراد المتوقّع)
  createdAt, createdBy
}]
```

### ٣-٢) موازنة المشروع (مستند مستقل لكل مشروع)

```
meta/{projectId}_budget  →  {
  categories: [                    // البنود العامة الثابتة المفعّلة لهذا المشروع
    { key:"electrical", name:"كهرباء", planned: 120000 }, ...
  ],
  boq: [                           // بنود المقايسة التفصيلية (اختياري لكن مُوصى به)
    { id, categoryKey:"electrical", desc:"تمديد 3 فاز", qty, unit, unitPrice, planned },
    ...
  ],
  updatedAt, updatedBy
}
```

- `planned` للبند العام = مجموع بنود المقايسة تحته (يُحسب تلقائياً) **أو** رقم مُدخل يدوياً
  لو المشروع لسه مبيتفصّلش بمقايسة.
- ربط بمحرك تحليل الأسعار الحالي (`price-analysis.js`) لاحقاً: بند المقايسة يقدر يتولّد من
  Rate build-up بدل الإدخال اليدوي.

### ٣-٣) الإيراد ودفعات العميل (مستخلصات)

```
meta/{projectId}_revenue  →  {
  invoices: [                      // المستخلصات / الفواتير للعميل
    { id, no, date, amount, desc, status:"submitted|approved|paid" }
  ],
  payments: [                      // دفعات العميل الفعلية الواردة
    { id, date, amount, ref, receiptUrl, by }
  ],
  updatedAt, updatedBy
}
```

> نفس فلسفة «السداد على دفعات» الموجودة في المشتريات (`payment.installments[]`) — بنعكسها
> على جهة العميل: مستحق مقابل مُحصَّل.

## ٤) الشاشات

### ٤-١) قائمة المشاريع (تطوير الشاشة الحالية)
بطاقات المشاريع الحالية + على كل بطاقة **٣ أرقام سريعة**: الموازنة / المصروف / نسبة الاستهلاك،
وشريط لون (أخضر ضمن الموازنة، أصفر قريب، أحمر متجاوز). فلترة بالحالة والنوع.

### ٤-٢) بطاقة المشروع (الشاشة الجديدة الأساسية) — تبويبات:

- **نظرة عامة:** ٤ بطاقات كبيرة (الموازنة / المصروف الفعلي / الإيراد / الربح) + شريط تقدّم
  مالي + بيانات العميل والعقد والتواريخ.
- **الموازنة:** جدول البنود العامة، وتحت كل بند بنود مقايسته، مع أعمدة:
  **الموازنة | المرتبط (طلبات جارية) | المصروف (مغلقة) | المتبقّي | %**.
- **المشتريات:** كل طلبات الشراء المربوطة بالمشروع (نفس بيانات المشتريات، مفلترة بالمشروع) —
  رابط مباشر للطلب في نظام المشتريات.
- **الإيراد:** المستخلصات ودفعات العميل، ومقارنة مستحق/مُحصَّل.
- **الربحية:** الإيراد − المصروف، بالمخطّط وبالفعلي، وهامش الربح %.

### ٤-٣) لوحة إجمالية لكل المشاريع
جدول: كل مشروع بصف — موازنة/مصروف/إيراد/ربح/حالة — مع إجماليات الشركة أسفل، وتنبيهات
المشاريع المتجاوزة للموازنة.

## ٥) الربط بالمشتريات (نقطة الارتكاز)

### الموجود بالفعل
- طلب الشراء فيه `projectId` + `projectName`.
- المشتريات بتجمّع **المصروف الفعلي لكل مشروع** من `poIsClosed` + `poActualCost`.

### الإضافة المطلوبة
1. **حقل «بند الموازنة» على شاشة طلب الشراء** (إضافة صغيرة): بعد اختيار المشروع، قائمة منسدلة
   بالبنود العامة للمشروع (واختياري: بند المقايسة). يُخزَّن `budgetCategoryKey` على الطلب.
2. **تجميع ثلاثي لكل بند:**
   - **المرتبط (Committed):** مجموع الطلبات **الجارية** المربوطة بالبند (`poStageIsWip`).
   - **المصروف (Actual):** مجموع الطلبات **المغلقة** (`poActualCost`).
   - **المتبقّي:** الموازنة − (المرتبط + المصروف).
3. **تنبيه تجاوز الموازنة:** عند إنشاء/اعتماد طلب هيخلّي (المرتبط + المصروف) يعدّي موازنة البند
   → تحذير واضح **قبل** الاعتماد (مبدئياً تحذير غير مانع؛ المنع خيار لاحق للأدمن).

> **ملاحظة توافق:** الطلبات القديمة بلا `budgetCategoryKey` تتجمّع تحت بند «غير مصنّف» فلا
> تختفي من الحساب.

## ٦) بنود الموازنة الهجينة (القرار)

**قائمة عامة ثابتة (مبدئية — عدّلها):**

| المفتاح | البند | يشمل |
|---|---|---|
| `materials` | خامات عامة | مواد بناء أساسية |
| `plumbing` | سباكة | مواسير، تشطيبات صحية |
| `electrical` | كهرباء | تمديدات، لوحات، إنارة |
| `plaster` | محارة/بياض | — |
| `finishes` | تشطيبات | دهانات، أرضيات، سيراميك |
| `carpentry` | نجارة | أبواب، وحدات |
| `aluminum` | ألوميتال/زجاج | — |
| `labor` | مصنعيات/عمالة | من كتالوج العمالة الحالي |
| `subcontractor` | مقاول باطن | بنود مسندة لمقاول |
| `equipment` | معدات/إيجارات | — |
| `overhead` | مصاريف إدارية | نقل، إشراف، متنوّع |
| `uncategorized` | غير مصنّف | التوافق مع الطلبات القديمة |

- **الثابت** = العمود الفقري (مقارنة بين المشاريع + ربط المشتريات + تقارير مجمّعة).
- **بنود المقايسة** = تحت كل بند عام، خاصة بكل مشروع (تفصيل ومرونة).
- القائمة العامة **قابلة للتعديل من لوحة الأدمن** (زي إعدادات المشاريع الحالية).

## ٧) حساب الربحية

```
المصروف الفعلي   = Σ poActualCost(الطلبات المغلقة للمشروع)  + دفعات العمالة/المقاولين
المرتبط          = Σ getPOTotal(الطلبات الجارية للمشروع)
الإيراد المُحصَّل  = Σ payments (دفعات العميل)
الإيراد المستحق   = Σ invoices approved (المستخلصات المعتمدة)

الربح الفعلي حتى الآن = الإيراد المُحصَّل − المصروف الفعلي
الربح المتوقّع للمشروع = contractValue − (الموازنة الكلية)
هامش الربح %          = الربح ÷ الإيراد × 100
```

> الأرقام كلها تمرّ على دوال المشتريات المركزية — فتطابق تقرير المشتريات تماماً.

## ٨) خارطة الطريق (٣ مراحل)

### 🟢 المرحلة ١ — الأساس المالي والربط بالمشتريات
- توسيع بطاقة المشروع (عميل/نوع/مدير/تواريخ/حالة).
- شاشة الموازنة بالبنود الهجينة + إدخالها.
- حقل «بند الموازنة» على طلب الشراء.
- التجميع الثلاثي (موازنة/مرتبط/مصروف/متبقّي) + شريط التقدّم.
- تنبيه تجاوز الموازنة (تحذيري).
- **الناتج:** تحكم مالي حقيقي فوري ومربوط بالمشتريات.

### 🟡 المرحلة ٢ — الإيراد والربحية
- قيمة العقد + المستخلصات + دفعات العميل.
- تبويب الربحية + هامش الربح.
- اللوحة الإجمالية لكل المشاريع + إجماليات الشركة.

### 🟠 المرحلة ٣ — الوقت والتنفيذ
- مراحل المشروع + نسب الإنجاز + مؤشر التأخّر (مخطّط مقابل فعلي زمنياً).
- تقارير موقع بالصور (استفادة من Storage الموجود).
- ربط بنود المقايسة بمحرك تحليل الأسعار (توليد الموازنة من Rate build-up).

## ١٠) نقاط مفتوحة للقرار (محتاج رأيك)

1. **قائمة البنود العامة:** توافق على القائمة في §٦ ولا تحب تعدّلها/تختصرها؟
2. **تنبيه التجاوز:** تحذيري فقط، ولا مانع (يمنع الاعتماد فوق الموازنة) — أو خيار للأدمن؟
3. **الإيراد:** «المستخلص» عندكم بيعتمد بمراحل معيّنة؟ محتاج أعرف دورته عشان أظبط الحالات.
4. **العمالة والمقاولين:** دفعات العمالة/المقاول بتتسجّل حالياً فين؟ (عشان تدخل في المصروف
   الفعلي مش بس طلبات الشراء).
5. **العملة:** المشروع في بالي — نشتغل بعملة واحدة (روبية/دولار) ولا محتاجين تعدّد عملات؟
