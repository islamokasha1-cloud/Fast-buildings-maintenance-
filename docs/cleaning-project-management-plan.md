# مستند تصوّر — إدارة مشاريع النظافة (عقود تشغيل النظافة)

> **اقرأني أولاً.** ده **مستند تصوّر للمراجعة والنقاش قبل كتابة الكود الكبير**. الهدف نتفق
> على الشكل والحقول والمنطق على الورق، وبعدين ننفّذ صح من أول مرة. كل رقم أو مسمّى هنا
> **مبدئي وقابل للتعديل** — علّق عليه وعدّله زي ما تحب.
>
> **الحالة:** مسودّة أولى — تنتظر قرارات صاحب النظام.
> **الفرع:** `claude/cleaning-project-type-xa5gnu`
> **العملة:** ريال (SAR) — عملة واحدة لكل الأرقام المالية.

---

## ٠) لماذا نوع جديد أصلاً؟ (الفكرة في سطرين)

مشاريع النظافة **ليست** مشاريع ببداية ونهاية زي المقاولات/الترميم، ولا هي تفاعلية بالبلاغات
زي الصيانة. هي **عقود تشغيل مستمرّة (شهرية/سنوية)** لمبنى أو مرفق: نفس العمل يتكرّر كل يوم،
والنجاح يُقاس بـ **الالتزام اليومي + الجودة + ضبط تكلفة العمالة**، مش بنسبة إنجاز مشروع يتسلّم.

لذلك يحتاج **أسلوب إدارة ومتابعة مختلف** — وده اللي المستند ده بيرسمه، بحيث نقدر نضيف
**أكثر من مشروع نظافة** تحت نفس النوعية ونديرها كلها بنفس المنطق.

---

## ١) الفرق بين الأنواع الثلاثة (لماذا النظافة مختلفة)

| البُعد | الصيانة | المقاولات / الترميم | **النظافة (الجديد)** |
|---|---|---|---|
| الطبيعة | تفاعلية (بلاغ → إصلاح) | مشروع ببداية/نهاية | **عقد تشغيل مستمر متكرّر** |
| الوحدة المحورية | البلاغ / أمر الشغل | المستخلص / نسبة الإنجاز | **اليوم التشغيلي + الوردية** |
| أكبر بند تكلفة | قطع الغيار | الخامات والمقاولين | **رواتب العمالة (المشرفون + العمّال)** |
| المتابعة | إغلاق البلاغات + SLA | الجدول الزمني (Gantt) | **الحضور + قوائم الفحص + جولات الجودة** |
| المخرَج المالي | مصروف صيانة | ربحية عند التسليم | **ربحية شهرية متكرّرة** |
| علامة الخطر | بلاغ متأخّر | تجاوز موازنة / تأخّر جدول | **نقص عمالة / مخالفة عميل / تدنّي جودة** |

**الخلاصة:** النظافة تحتاج بطاقة مشروع بتبويبات مختلفة تماماً — لا «مقايسة» ولا «جدول زمني
بالمراحل»، بل **طاقم + حضور + مهام دورية + جودة + ربحية شهرية**.

---

## ٢) المبادئ الحاكمة

1. **نبني فوق الموجود.** المشروع كيان قائم (`meta/projects`) بحقل `type`. نضيف قيمة رابعة
   `"cleaning"` فقط — ولا نعيد اختراع كيان المشروع.
2. **بند «مواد نظافة» موجود بالفعل** في المشتريات (`cleaning`). مستهلكات النظافة (منظّفات،
   مهمّات) تُسحب منه تلقائياً كمصروف فعلي — بلا إدخال مزدوج.
3. **مصدر واحد للحقيقة.** المصروف من المشتريات يمرّ على نفس دوال النواة
   (`poIsClosed`/`poActualCost`/`poStageIsWip`). رواتب العمالة مصدرها وحدة الطاقم الجديدة.
4. **لا انحدار.** المشاريع الحالية (صيانة/مقاولات/ترميم) تفضل تشتغل زي ما هي بالضبط. النوع
   الجديد لا يغيّر سلوك أي نوع قائم.
5. **إعادة استخدام السباكة:** الأدوار، الإشعارات (`HailNotify`/واتساب)، المرفقات (Storage)،
   والذكاء الاصطناعي (`_aiText`) — كلها قائمة ونعيد استخدامها بدل بناء جديد.
6. **التدرّج.** كل مرحلة تشتغل لوحدها وتدّي قيمة؛ نبدأ بالأساس المالي ثم التشغيلي.

## ٣) نموذج البيانات (مبدئي)

### ٣-١) تصنيف النوع (المرحلة ١ — الأساس)
- على سجل المشروع: `type: "cleaning"` (يُختار من نافذة تعديل المشروع مثل باقي الأنواع).
- في بطاقة المشروع: نفس آلية `saveType` الحالية تدعم القيمة الجديدة.

### ٣-٢) إعدادات عقد النظافة (مستند مستقل لكل مشروع)
```
meta/{projectId}_cleaning  →  {
  monthlyValue,                 // قيمة العقد الشهرية (الإيراد المتكرّر) — بالريال
  startDate, renewDate,         // بداية العقد / تاريخ التجديد
  sites: [                      // المواقع/المناطق تحت العقد (مبنى A، الأدوار، المواقف…)
    { id, name, notes }
  ],
  contractedHeadcount,          // العمالة المتعاقد عليها (للمقارنة بالحضور الفعلي)
  updatedAt, updatedBy
}
```

### ٣-٣) الطاقم (مجموعة لكل مشروع)
```
{projectId}_crew  (مجموعة)  →  كل مستند فرد:
  { id, name, role:"worker"|"supervisor", monthlySalary, siteId, shift, active, createdAt }
```
- رواتب الطاقم = أكبر بند في **الربحية الشهرية** (§٥).
- ربط اختياري لاحقاً بكتالوج العمالة الحالي (`labor-catalog.js`).

### ٣-٤) الحضور (مجموعة لكل مشروع)
```
{projectId}_attendance  (مجموعة)  →  كل مستند يوم/فرد:
  { id, date, workerId, siteId, status:"present"|"absent"|"leave", by, at }
```
- النقص عن `contractedHeadcount` = مؤشّر خطر (تنبيه واتساب اختياري).

### ٣-٥) المهام الدورية / قوائم الفحص (مستند لكل مشروع)
```
meta/{projectId}_cleaning_tasks  →  {
  tasks: [
    { id, siteId, area, task, freq:"daily"|"weekly"|"monthly"|"periodic",
      lastDoneDate, active }
  ], updatedAt, updatedBy
}
```
- توليد أوّلي بالـ AI (قائمة فحص مقترحة حسب نوع المبنى) ثم تحرير يدوي.

### ٣-٦) جولات التفتيش / الجودة (مجموعة لكل مشروع)
```
{projectId}_inspections  (مجموعة)  →  كل جولة:
  { id, date, by, siteId, score,          // تقييم 1..5 أو %
    notes, photos:[urls], clientRating,   // صور قبل/بعد + تقييم العميل
    violations:[{desc, severity, resolved}] }
```

> **المصروف الفعلي لا يُخزَّن** — يُحسب لحظياً من (مستهلكات المشتريات + رواتب الطاقم) مثل
> باقي النظام.

## ٤) بطاقة مشروع النظافة — التبويبات (مختلفة عن الأنواع الأخرى)

| التبويب | الوظيفة |
|---|---|
| **نظرة عامة** | قيمة العقد الشهرية · الربحية الشهرية · عدد الطاقم مقابل المتعاقد · مؤشّر الجودة · حالة الحضور اليوم |
| **الطاقم والمواقع** | عمّال ومشرفون موزّعون على المواقع/الورديات + إجمالي الرواتب الشهرية |
| **الحضور** | متابعة يومية (من حضر/غاب) + نسبة الالتزام + تنبيه نقص |
| **المهام الدورية** | قوائم فحص يومي/أسبوعي/شهري لكل منطقة + نسبة الإنجاز |
| **الجودة والتفتيش** | جولات بتقييم وصور + ملاحظات ومخالفات العميل |
| **المستهلكات** | مواد النظافة من المشتريات (بند `cleaning`) مفلترة على المشروع |
| **الربحية الشهرية** | الإيراد الشهري − (رواتب + مستهلكات + إدارية) = صافي الشهر وهامشه % |

> ملاحظة: هذه البطاقة **بديلة** لبطاقة المقاولات (لا تظهر «المقايسة» ولا «الجدول الزمني»
> بالمراحل)؛ يتفرّع العرض حسب `type` داخل نفس وحدة إدارة المشاريع.

---

## ٥) الربحية الشهرية (قلب النظافة)

```
صافي الشهر = قيمة العقد الشهرية
           − إجمالي رواتب الطاقم النشط
           − مستهلكات النظافة (بند cleaning من المشتريات لهذا الشهر)
           − مصاريف إدارية (اختياري)
هامش الربح % = صافي الشهر ÷ قيمة العقد الشهرية
```
- عرض شهري متتابع (آخر ١٢ شهر) لرؤية اتجاه الربحية لكل عقد نظافة.
- تنبيه تحذيري لو الهامش نزل تحت حدّ يحدّده الأدمن.

## ٦) بنية الملفات (على نمط النظام الحالي)

| الملف | الوظيفة |
|---|---|
| `project-management.js` (تعديل) | تفريع بطاقة المشروع حسب `type==="cleaning"` لعرض تبويبات النظافة. |
| `cleaning-management.js` (جديد) | وحدة النظافة — الطاقم، الحضور، المهام، الجودة، الربحية الشهرية. تعرض `window.cleaningMgmt`. |
| `index.html` (تعديل بسيط) | خيار «إدارة نظافة» في نافذة تعديل المشروع + حقن الوحدة الجديدة. |
| `hail-tests.js` (تعديل) | فحوص Node لمنطق الربحية الشهرية وتجميع الحضور والمستهلكات. |

> نمشي على نفس نمط الوحدات المستقلة (IIFE تعرض كائناً على `window`، تقرأ خدمات النواة
> بالاسم: `db`/`esc`/`toast`/فحوص الأدوار). وأي تعديل على وحدة `.js` **يرفع `APP_VERSION`
> وكل cache-busters وبصمة build معاً** (يفحصها `hail-tests.js`).

## ٨) خارطة الطريق (مراحل التنفيذ)

### 🟢 المرحلة ١ — الأساس: تسجيل النوع + بطاقة العقد المالية
- إضافة قيمة `"cleaning"` لنوع المشروع (نافذة التعديل + بطاقة المشروع + شارة/أيقونة).
- بطاقة نظافة مبدئية: قيمة العقد الشهرية + إدخال إجمالي رواتب الطاقم + سحب مستهلكات
  `cleaning` من المشتريات → **الربحية الشهرية** تشتغل فوراً.
- **الناتج:** تقدر **تضيف مشروع النظافة بتاعك دلوقتي** وتراقب ربحيته الشهرية.

### 🟡 المرحلة ٢ — التشغيل: الطاقم والحضور
- إدارة الطاقم (عمّال/مشرفون/رواتب/مواقع/ورديات).
- متابعة الحضور اليومي + نسبة الالتزام + تنبيه نقص العمالة (واتساب).

### 🟠 المرحلة ٣ — الجودة: المهام والتفتيش
- قوائم الفحص الدورية (توليد بالـ AI + تحرير) ونسب الإنجاز.
- جولات التفتيش بالتقييم والصور + ملاحظات ومخالفات العميل.

## ٩) نقاط تحتاج قراراً قبل التنفيذ الكبير

1. **نطاق البدء:** نكتفي بالمرحلة ١ (تسجيل النوع + البطاقة المالية) عشان تضيف مشروعك فوراً،
   ثم نبني التشغيل والجودة تدريجياً؟ أم نبدأ بمنطقة مختلفة؟
2. **العمالة:** إدخال إجمالي الرواتب يدوياً في البداية (أبسط)، ولا طاقم مفصّل من أول يوم؟
3. **الحضور:** تسجيل يدوي بسيط (حاضر/غائب) يكفي، ولا محتاج ورديات ونِسب دقيقة من البداية؟
4. **الجودة:** قوائم فحص + صور تكفي، ولا محتاج تقييم عميل رسمي بتوقيع؟
5. **الأدوار:** «مدير التشغيل» و«المشرف الميداني» — موجودان كأدوار، ولا ننشئهما؟
